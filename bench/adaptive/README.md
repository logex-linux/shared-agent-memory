# Adaptive retrieval evaluation protocol (frozen before measurement)

Corpus: 240 fictional records; 120 queries in 10 categories, 12 each. Labels are derived from explicit scenario keys in fixtures.mjs, never from retrieval scores. Frozen fixture SHA256: e05f6626130ae14b31bad2fe81a24d81ec31bf3e1307477ffa9d76af2478488b.

Each technical scenario has an adopted repair and independent review, with a rejected proposal as a hard negative. Design history contains 72 relevant records across six projects, 24 months and six themes: direct statements, behavior observations, unconfirmed model inference, conflicting and temporary requirements. A narrower theme query labels only its twelve records. Production queries exclude expired/development instructions. Twelve topics absent from the corpus test abstention. Sources are fictional and auditable; these judgments are not human-user validation and cannot establish real-world performance.

Grades: 2 for explicitly relevant evidence; 0 otherwise. A contradiction or unconfirmed inference may be relevant evidence without being true. Labels do not change for a better score. P@k uses denominator k (unfilled positions count zero), R@k uses all labeled records, MRR uses first relevant, nDCG uses graded gain 2^grade-1 and ideal ordering. No-answer queries are excluded from recall/MRR/nDCG means and evaluated separately for erroneous related_evidence status. Precision, irrelevant fraction, tokens, duplicate fraction, counts and cumulative coverage are reported. Page sessions continue until has_more=false; the runner detects cursor loops, not an arbitrary record cap.

A/B uses the same immutable database snapshot, FP32 model and thresholds .425/.575, independent fresh processes, identical requested modes/views/limits where supported. v0.3 ignores new fields and permits at most ten returned records with no cursor; default five applies. Its P/R@20 therefore include unfilled positions and are explicitly capacity-limited, not an invented second page. Both default behavior and matched limit=5 size tests must be reported. Retrieval scores must not be used to revise these labels. Record initial model cold latency separately from warmed queries.

Run `node scripts/benchmark-adaptive.mjs build DIR`, then `... measure DIR DIST` with either frozen v0.3 dist or current dist. Raw databases/reports go in .local and are not committed. Synthetic fixtures and evaluation code are public.
