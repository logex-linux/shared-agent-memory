# 本地规模实测 · 2026-10-22

0.2.0 保留按可见项目过滤后的精确向量扫描。10,000 条短记忆的实测 p95 约 370 ms，进程峰值约 683 MiB，低于这次用于评估是否需要改引擎的 1 秒 / 1 GiB 阈值。阈值是本次工程判断尺度，不是对所有机器和工作负载的承诺；扫描成本仍随可见向量块数量增长。这次没有迁移向量数据库，也没有把现有实现称作 ANN。

## 方法

macOS arm64，Node 24.18.0，本地 bge-small-zh-v1.5，CPU FP32、512 维、2 线程。基线为提交 `70e8a4199234ffd068ce8f144fef5d031907f0c2` 的编译代码；与 0.2.0 使用同一批数据库快照。每个版本、每个规模单独进程，先基线后修复版；回归任务已结束。报告记录编译文件、脚本和查询集 SHA-256。

真实调用编码器构建 100、1,000、10,000 条记忆，每条恰好一个向量块，没有使用随机向量。20 条手写中文操作经验作为 gold，另外从 20 类无关主题生成带编号干扰记录。20 个改写查询各测 3 轮（60 次），每个进程另做 1 次预热。计时覆盖核心 recall 的查询编码、SQLite 与融合排序；不含 MCP 传输和首次模型加载。每次都检查返回 hybrid，降级会失败。

每个查询只有一条 gold，因此 Recall@5 等于前五命中率。查询集与干扰文本范围小，且非盲测；100% 不能解释为真实历史记忆检索的普遍准确率。RSS 是查询后采样；进程峰值来自 OS 的 maxRSS，包含模型启动。它不是单次查询的独占内存。

## 复现

先按 README 安装依赖和固定模型，再执行：

```sh
node scripts/benchmark-scale.mjs build .local/scale-benchmark
node scripts/benchmark-scale.mjs measure .local/scale-benchmark dist 100
node scripts/benchmark-scale.mjs measure .local/scale-benchmark dist 1000
node scripts/benchmark-scale.mjs measure .local/scale-benchmark dist 10000
```

比较旧版时，把旧提交单独编译后将 `dist` 参数替换为其编译目录；脚本为每个 kernel 复制快照，避免 schema4 升级影响旧版。完整首次构库会逐条编码，耗时明显长于检索。

## 决策范围

本次证据足以支持个人规模下先保留简单实现。未证明长篇多分块记忆、10,000 条以上数据、冷启动或多进程并发查询的性能。如果这些场景成为瓶颈，应先用实际分块分布和并发任务重测，再比较 sqlite-vec KNN、分区或两阶段候选；不能把这次合成测试外推为无限扩容能力。
