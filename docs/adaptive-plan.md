# 0.4.0 审计与实施方案

0.3.0 的 limit 默认5/最大10，三个候选通道各20，未返回条目没有cursor。普通响应每次包含完整diagnostics。晚物化已正确实现，Schema5、权限和记忆生命周期继续保留。

本次以页面预算替代累计数量上限：auto/focused/broad，独立候选通道分批继续，只有当前页入选记录物化。broad使用来源、项目、时间、主题的新颖性，在相关候选内调整多样性。focused根据明确标识符、多通道支持、相关分布落差减少返回；不足时保留insufficient。启发式不是事实证明，分页可继续探索。

辅助SQLite查询缓存保存轻量候选、通道进度和不可变页面选择，不存正文/来源。游标绑定查询、排序版本、配置权限摘要、注册项目摘要和generation；每次续取重新检查权限、有效期和版本。写入或遗忘后拒绝旧游标。缓存使用WAL、短写事务、随机查询ID、滑动TTL；崩溃后可重放已提交页面，不存在缓存时明确重查。缓存可删除，canonical Schema5不变；没有新常驻服务。

单页限制为可配置bytes、估算tokens、候选工作量、协作式时间预算和较大条目数保护。没有累计条目上限。游标不采用OFFSET；通过已检索Memory的索引反连接继续。单个原生SQL不可被JS计时器抢占，时间预算不能宣传为硬实时超时。

先冻结0.3.0及多相关答案标注集，再做A/B。评估数据必须是虚构场景和事先确定的相关等级，涵盖无答案、长偏好历史、冲突、失效、近似负例。保持旧测试的业务断言；诊断断言显式debug。验证多进程分页重放、并发写入失效及真实BGE召回，最后发布代码及通用文档到GitHub；真实库和客户端配置不升级。
